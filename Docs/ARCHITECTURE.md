# Архитектура IPA Desktop 0.3

Приложение использует **Avalonia 12, современный C# и .NET 10**. Целевая платформа текущего выпуска — Windows x64. Перенос сервисов ConPTY, Apple Support, корзины и нативных инструментов на другие ОС выполняется отдельно.

## Структура

| Путь | Назначение |
|---|---|
| `IPA-Desktop.csproj`, `global.json` | SDK-проект и выбор .NET 10 SDK |
| `App.axaml`, `MainWindow.axaml` | Общая тема и главное окно, компилируемые в ресурсы |
| `Source/Domain` | Модели, правила выбора, прогресс, отчёты |
| `Source/Infrastructure` | Процессы, ConPTY, HTTP, JSON, файлы, поиск инструментов, Windows Apple Support |
| `Source/Services` | Вход, каталог, скачивание, установки, наборы, обновления |
| `Source/Presentation` | Avalonia-приложение, окна и контроллеры вкладок |
| `Tests/Modern` | xUnit v3: сервисные контракты, JSON, IPA, реальные окна Avalonia и сценарии Windows |
| `Tests/LoginFixture` | Консольный процесс для проверки реального ConPTY без аккаунта Apple |
| `Tests/Fixtures` | Неизменённый helper 0.2.12 и его список файлов для проверки обновления |
| `Scripts` | Упаковка и проверка установленного приложения, обновляющий helper |
| `Tools/DeviceTools` | Независимая сборка и тесты инструментов iPhone |

`Generated`, csc и .NET Framework больше не участвуют в сборке. Все классы из Source компилируются SDK-проектом. Зависимости NuGet закреплены в csproj.

## Интерфейс и операции

`Desktop` собирает контроллеры и управляет текущей операцией, отменой и журналом. Сервисы не зависят от Avalonia. UI обновляется только через диспетчер Avalonia. Диалоги показываются асинхронно и ожидаются вызывающим действием; подтверждения не создают вложенные циклы сообщений.

Очереди перед запуском копируются. `BatchRunner` продолжает работу после ошибки отдельного элемента и останавливается при отмене. Повтор использует снимок неудачных элементов. Идентификаторы скачиваний включают ID приложения и версии; установки привязаны к пути IPA.

Таблица версий использует ObservableCollection и уведомления AppVersionRow. Получение метаданных не пересоздаёт таблицу и не теряет множественный выбор. Изменение поискового запроса отслеживается через синхронное изменение свойства Text, чтобы быстрый Enter или программный поиск не опережал обработку отложенного TextChanged.

Фильтры Apple Account используют метаданные IPA и не меняют сессию. Выбранные IPA сохраняются между фильтрами; скрытые элементы учитываются в счётчике и подтверждении установки/удаления.

## Вход и данные

Окно входа использует маскированные TextBox Avalonia для пароля и 2FA, очищая их после отправки и закрытия. Значения передаются сервису через короткоживущие SecureString. Как и другие текстовые UI-контролы, TextBox хранит текст в управляемой памяти; оболочка не записывает его в файл, журнал или аргументы процесса.

`AppleLoginService` сохраняет Windows ConPTY и штатный протокол ipatool: каждый этап отправляется один раз, перерисовки не повторяют пароль и код, попытка ограничена пятью минутами. После входа проверяется сохранённая сессия. Сам ipatool хранит свои данные в зашифрованном файле `.ipatool` профиля Windows.

`JsonCodec` использует System.Text.Json с сгенерированными метаданными типов. Сохранены прежние имена и значения по умолчанию State, формат AppSets и контракт словарей/массивов для ответов ipatool. Рабочая папка остаётся `%LOCALAPPDATA%\IPA-Desktop`. История версий инструментов и IPA не переносятся и не удаляются при миграции.

Импорт копирует данные асинхронно во временный файл с отменой внутри копирования. Полная копия переименовывается без перезаписи существующего IPA. Ошибка или отмена удаляет временный файл. Удаление пользовательских IPA по-прежнему использует корзину Windows.

## Автоопределение iPhone

Контроллер проверяет устройства каждые три секунды между операциями. Поиски не пересекаются. Перед рабочей командой и закрытием окна поиск отменяется с ожиданием завершения дочернего процесса. Результат старого режима USB/Wi-Fi не применяется.

Выбор сохраняется по UDID и транспорту. Один обнаруженный вариант подключения выбирается автоматически; исчезновение выбранного телефона не переключает действия на другой. Одинаковые предупреждения не заполняют журнал. После ошибки поиск возобновляется на следующем цикле.

Установка проверяет платформу IPA и минимальную iOS, подтверждает устройство и готовит ASCII-имя через hard link или копирование. При обрыве Wi-Fi нет скрытого повтора или переключения на USB.

## Выпуск и обновления

GUI, ipatool и device-tools обновляются независимо. Новые инструменты проверяются в отдельной GUID-папке до переключения настроек; прежняя версия остаётся для отката.

Windows-сборка публикуется как автономный single-file EXE: .NET 10, Avalonia, Skia и ресурсы включены. Runtime отдельно не устанавливается. Используется частичное сокращение системных библиотек; приложение и отражаемые элементы Avalonia явно сохранены через TrimmerRootAssembly. Модели для JSON используют source generation. Проверка готового EXE подтверждает, что строковые UI-привязки не были удалены.

`package-files.json` — источник состава современного пакета. Он встроен в приложение и используется updater/helper. `Scripts/package.py` также добавляет небольшие совместимые записи для прежних helpers, не участвующие в запуске или сборке. Проверяются ограничения 0.2.12: EXE до 32 МиБ и ZIP до 64 МиБ.

Windows CI применяет архив неизменённым `Update-App-0.2.12.ps1`, запускает уже установленный EXE без общего DOTNET_ROOT, проверяет настройки/наборы, JSON, поиск и окна входа/версий. Затем проверяется новый helper. Пользовательские IPA сохраняются. Опубликованные архивы никогда не перезаписываются.

## Проверки

```powershell
dotnet restore Tests/Modern/IPA-Desktop.Tests.csproj
dotnet build Tests/Modern/IPA-Desktop.Tests.csproj -c Release
dotnet Tests/Modern/bin/Release/net10.0-windows/IPA-Desktop.Tests.dll
```

Локальный запуск headless-проверок на другой ОС помогает тестировать Avalonia, но не означает поддержки той ОС готовым приложением. ConPTY проверяется в CI приложения; настоящие EXE инструментов — при выпуске device-tools. Установка на физический iPhone и полный вход с личным аккаунтом Apple остаются отдельными аппаратными проверками.

```bash
PYTHONPATH=Tools/DeviceTools python -m unittest discover -s Tools/DeviceTools/Tests -v
```

Подробный порядок CI — `.github/workflows/release.yml`.

## Проверка доверия и остановка очереди (0.3.1)

`DeviceReadiness` выполняет validate + чтение UniqueDeviceID до запуска установщика. При Invalid HostID пробует pair; только после подтверждённой ошибки устаревшей записи выполняет unpair с тем же `-u UDID` и pair. Повторы ожидания доверия ограничены 90 секундами и общим токеном отмены. По Wi-Fi восстановление не подменяет выбранный транспорт: требуется USB.

`DeviceConnectionException` отличает общую проблему связи от ошибки конкретного IPA. BatchRunner фиксирует ошибку текущего элемента и прекращает очередь, сохраняя не начатые элементы. При отказе handshake установщика DeviceInstallation восстанавливает доверие и повторяет только текущий пакет, не больше одного раза. FilesController блокирует установку и повтор для этой пары UDID/транспорт до успешной команды «Проверить связь».

`ErrorLocalizer` сопоставляет известные ответы с причиной и действием. Неизвестный код не получает выдуманную причину. Отчёт сохраняет технический ответ, а основное окно показывает локализованные инструкции. Пароль и 2FA по-прежнему обрабатывает отдельный приватный канал авторизации.

## Публикация из main

Изменения вносятся непосредственно в main без временных веток и PR. Выпуск приложения запускается при изменении версии в csproj либо вручную. Уже опубликованная версия не пересобирается при обычном push; ручной запуск проверяет её без перезаписи релиза. Заметки берутся из changelogs при публикации, отдельного workflow синхронизации старых описаний нет.

CI приложения проверяет сервисы, очереди, сопряжение, вход, настройки и запуск готового пакета с обновляющим helper. Скриншоты и их артефакты автоматически не создаются. Тесты упаковки и запуск настоящих native EXE выполняет только workflow device-tools. В нём восстановление готового черновика и сборка используют один Windows job.
