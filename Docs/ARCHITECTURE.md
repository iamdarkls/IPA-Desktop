# Архитектура и сопровождение

IPA Desktop использует **C# 5, WPF и .NET Framework 4.6+**. Исходники находятся в `Source`, переносимые файлы для штатного компилятора Windows — в `Generated`. Форматы настроек, наборов и пакет обновления совместимы с прежними версиями.

## Карта репозитория

| Каталог | Содержимое |
|---|---|
| `Source/Domain` | Модели и правила: Applications, Devices, Storage, Operations, Updates |
| `Source/Infrastructure` | Accounts, Processes, Storage, Tools, Networking, Logging, Devices |
| `Source/Services` | Операции с аккаунтами, приложениями, устройствами, хранилищем и обновлениями |
| `Source/Presentation` | Контроллеры и окна по функциям; общие элементы в Shared |
| `Generated` | Снимки для компиляции; вручную не редактируются |
| `Assets` | Иконка и исходный SVG |
| `Tests` | Windows-проверки моделей, сервисов, WPF, входа и обновления |
| `Scripts` | Синхронизация снимков, ресурсы, упаковка и обновление GUI |
| `Tools/DeviceTools` | Независимая сборка нативных инструментов; свои Scripts, Tests и device_tools |
| `Docs` | Документация разработчика и обзор интерфейса |
| `changelogs` | Описания GUI-релизов |

`Engine` в корне Services собирает зависимости. `Desktop` в корне Presentation управляет временем жизни окна, отменой, журналом и текущей операцией. Остальные классы размещаются в подкаталогах по ответственности. Пространство имён `IpaDesktop` сохраняет совместимость с переносимой сборкой и проверками.

## Границы слоёв

- **Domain** не зависит от WPF и процессов. Очереди идентифицируют приложения по ID/версии, IPA — по пути; название не является ключом.
- **Infrastructure** изолирует файловую систему, Win32, HTTP и запуск процессов. `IProcessRunner` и `ILoginProcessFactory` подменяются в тестах.
- **Services** выполняют операции без ссылок на элементы интерфейса. `IAppToolClient` отделяет сценарии приложения от формата команд ipatool.
- **Presentation** хранит выбор вкладки и вызывает сервисы. Длительная работа выполняется асинхронно; фоновые потоки не обращаются к WPF напрямую.

Снимки очередей копируются перед запуском. `BatchRunner` последовательно обрабатывает элементы, продолжает после обычной ошибки и останавливается при отмене. `OperationReport` хранит результаты отдельно от ограниченного журнала. Повтор использует только неудачные элементы текущего сеанса.

## Аккаунт и приватный вход

`AppleLoginWindow` собирает пароль и 2FA через PasswordBox. `AppleLoginService` запускает штатный `auth login --format json` через ConPTY Windows 10 1809+, затем отдельно проверяет `auth info`: старая сессия и ошибка сохранения не считаются успешным входом.

Секреты не передаются аргументами CLI. Временные массивы очищаются, поля освобождаются после отправки. Сырой интерактивный поток не подключён к журналу; наружу выходят только фиксированные сообщения ошибок. Протокол принимает каждый этап один раз, допускает фрагменты ANSI и повторную отрисовку запросов без повторной отправки пароля/кода. Попытка ограничена пятью минутами, отмена завершает дочерний процесс.

Upstream ipatool сохраняет данные аккаунта, включая пароль, в зашифрованном файле `.ipatool` профиля Windows. Оболочка не создаёт дополнительную базу паролей. CI проверяет настоящий ipatool только до отправки пароля; полный вход с личным аккаунтом требует отдельной проверки.

## Поиск, файлы и производительность

`AppCatalog` объединяет каталог IPA_Downloader, пользовательский файл и результаты ipatool. Содержимое каталога и метаданные IPA кэшируются с учётом изменений файлов. Переключение фильтра аккаунта работает по снимку `LocalRow`, не сканирует диск и не меняет аккаунт входа. Общая очередь установки сохраняется между фильтрами; скрытый выбор учитывается в счётчике и подтверждении.

Если обновление каталога не удалось, поиск использует сохранённую копию; через 30 секунд следующий поиск снова пробует обновить каталог. Успешный ответ кэшируется до конца сеанса. Явная отмена пользователя не включает задержку повторной попытки.

Импорт IPA копирует данные асинхронно с отменой внутри файла во временное имя `.import-*.tmp`. Полностью записанный файл переименовывается в IPA без замены существующего файла. При ошибке или отмене временная копия удаляется; ранее импортированные файлы сохраняются.

`ToolLocator` кэширует найденные EXE отдельно для активного движка и комплекта устройств. Установщик всегда создаёт новую GUID-папку версии. Смена выбранной папки или откат очищает соответствующий кэш; исчезнувший EXE запускает повторный поиск. Ошибки и неоднозначные результаты не кэшируются. При поиске достаточно двух совпадений, чтобы отклонить неоднозначный комплект. Ручное добавление бинарников в уже активную папку не поддерживается; для изменения комплекта используйте установку/обновление.

`StorageAnalysis` разбирает каждую числовую версию один раз. Старые версии определяются только при известных Bundle ID и аккаунте, отдельно для каждого аккаунта. `AtomicFile` сохраняет настройки и наборы через уникальный временный файл. Удаление IPA ограничено рабочей папкой и использует корзину.

`FileTransferMeter` измеряет рост временного файла по ограниченному окну монотонных отсчётов. Это приблизительная скорость получения IPA, а не измерение канала. Наблюдатель отменяется и дожидается завершения вместе с загрузкой. Журнал обновляется пакетно через ограниченный `BufferedJournal`.

## Установка на iPhone

`DeviceService` — фасад; `DeviceCommandClient` задаёт CLI, транспорт, таймауты и проверку идентификатора; `DeviceDiscovery` независимо ищет USB/Wi-Fi; `DeviceInstallation` проверяет совместимость и выполняет установку.

`FilesController` автоматически проверяет устройства каждые 3 секунды, без блокировки основных действий. Поиски не пересекаются. Перед любой рабочей операцией `Desktop.Work` отменяет фоновый поиск и дожидается завершения его CLI; после операции автоопределение возобновляется. Закрытие окна также дожидается отмены поиска. Результаты устаревшего режима USB/Wi-Fi не применяются. Неизменный список не пересоздаётся, выбор сохраняется по UDID и транспорту. Один новый iPhone выбирается автоматически; исчезновение выбранного устройства не переключает действия на другой телефон. Ошибки и предупреждения показываются в статусе/подсказке, одинаковые предупреждения не заполняют журнал.

Имена устройств запрашиваются до 5 секунд каждое и 15 секунд суммарно. При недоступном имени остаётся короткий UDID. Перед подготовкой большого IPA проверяются исходные метаданные и связь с телефоном; затем повторно читаются метаданные фактически отправляемого файла. `InstallationPackage` создаёт временное ASCII-имя через hard link или копирование с отменой. Исходный файл сохраняется.

Выбранный транспорт сохраняется для всех команд. При обрыве Wi-Fi нет автоматического повтора и переключения на USB. Неизвестные сведения о платформе/iOS не считаются подтверждением совместимости; окончательную проверку выполняет iPhone.

## Обновления и совместимость

GUI, ipatool и device-tools обновляются независимо. `EngineUpdater` получает ipatool из Sorvigolova/ipatool, комплект устройств — из наших `device-tools-v…`. Новые файлы и CLI проверяются до переключения настроек; прежний комплект остаётся для отката. IPA_Downloader поставляет только каталог.

`GuiUpdater.PackageFiles`, `Scripts/Resources.rsp` и `Scripts/Update-App.ps1` описывают переносимый пакет. При изменении его состава обновляйте все три списка и `Verify-Layout`. Пакет содержит совместимые корневые псевдонимы для обновления старых установок. Внутреннее перемещение Source не меняет пути переносимого пакета.

Device-tools разделены на библиотеку `device_tools`, точки входа `Scripts` и автономные `Tests`. Упаковщик строит замыкание DLL через индекс и очередь, считает SHA-256 потоково и собирает пакет в чистом временном каталоге. ZIP заменяется только после успешного сжатия. Подробности процесса публикации и лицензий — в [Device Tools](../Tools/DeviceTools/README.md).

## Сборка и проверки

В Windows из корня репозитория:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File Scripts/Sync-Sources.ps1
.\Build.cmd
powershell -NoProfile -ExecutionPolicy Bypass -File Scripts/Sync-Sources.ps1 -Check
powershell -NoProfile -STA -ExecutionPolicy Bypass -File Tests/Verify-Services.ps1
powershell -NoProfile -STA -ExecutionPolicy Bypass -File Tests/Verify-AppleLogin.ps1
```

`Build.cmd` сам запускает синхронизацию, если присутствует Source, и останавливает сборку при её ошибке. Переносимая сборка без Source использует готовые Generated. Синхронизация рекурсивно находит классы внутри слоёв; специальные снимки IpaMetadata, WindowTheme и GuiUpdater остаются отдельными. Перед коммитом обновляйте Generated. Скрипты PowerShell с кириллицей сохраняйте в UTF-8 с BOM для Windows PowerShell 5.1.

Полный набор проверок указан в [Windows workflow](../.github/workflows/release.yml): метаданные, сервисы, WPF, приватный вход, движок, наборы, прогресс, очистка диагностики, пакет и обновление прежних установок. Native-тесты запускаются без сети:

```bash
PYTHONPATH=Tools/DeviceTools python -m unittest discover -s Tools/DeviceTools/Tests -v
```

Для GUI-релиза согласуйте AppInfo.Version, версию в XAML и `changelogs/v<версия>.md`. Версия native-комплекта задаётся отдельно. Пройденный CI не заменяет проверку входа и установки на физическом iPhone.
