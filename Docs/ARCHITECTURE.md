# Архитектура IPA Desktop

Проект использует C# 5, WPF и .NET Framework 4.6+. Архитектура разделяет обязанности классов, сохраняя поведение интерфейса и формат настроек.

| Папка | Обязанность | Основные классы |
|---|---|---|
| ../Source/Domain | Данные и правила выбора без зависимости от WPF | State, AppRow, LocalRow, DeviceRow, DownloadSelection, InstallationSelection, SearchSession |
| ../Source/Infrastructure | Операции с ОС и форматами данных | ProcessRunner, SettingsStore, ToolLocator, IpaMetadata, JsonCodec, BufferedJournal |
| ../Source/Services | Прикладные операции | AppToolClient, ApplicationDownloads, AppCatalog, DeviceService, AppleSupportService, LocalAppRepository, EngineUpdater, GuiUpdater |
| ../Source/Presentation | Отображение и обработка действий | Desktop, AccountController, SearchController, FilesController, AppSetsController, StorageController, UpdatesController, WindowController |

Desktop создаёт контроллеры, управляет временем жизни окна, журналом, отменой и состоянием текущей операции. Контроллер каждой вкладки хранит её выбор и подключает обработчики кнопок. Для операций с файлами и устройствами контроллеры обращаются к сервисам.

Engine — фасад: собирает сервисы и сохраняет существующий API адаптера. Запуск процесса реализован через IProcessRunner, команды ipatool — через IAppToolClient. Их можно подменить при проверках без настоящего Apple Account или iPhone.

Модели состояния совместимы с state.json прежних версий. Имена свойств release/asset соответствуют GitHub API. Проверка обновлений GUI сохраняется при установке и откате движка.

## Источники инструментов

EngineUpdater получает Windows x64 ZIP напрямую из Releases Sorvigolova/ipatool и проверяет запуск CLI до переключения настроек. State.Source и PreviousSource различают источники даже при совпадении номеров версий. Старые настройки без этих полей продолжают работать с прежним комплектом.

DeviceCurrent и DeviceVersion указывают отдельный комплект для установки на iPhone. При миграции используется существующий комплект; при чистой установке скачивается наш отдельный релиз device-tools-v… из iamdarkls/IPA-Desktop. Обновление и откат ipatool сохраняют DeviceCurrent. Отдельные CheckDeviceTools/InstallDeviceTools/RollbackDeviceTools проверяют наш релиз, распаковывают EXE/DLL, лицензии и сведения об исходниках в новую папку, проверяют --version у трёх утилит и атомарно сохраняют состояние. PreviousDeviceCurrent/PreviousDeviceVersion сохраняют независимый откат; AutoUpdateDeviceTools управляет отдельной проверкой при запуске. State.Copy сохраняет все настройки при переключении любого компонента. AppCatalog независимо получает AppsList.txt из IPA_Downloader и использует локальную копию при ошибке сети.

Verify-Engine.ps1 проверяет разделение источников, избирательный импорт, сохранение настроек и откат. С -Live он скачивает настоящие опубликованные Windows-архивы и запускает только справку ipatool, без входа в Apple Account и скачивания приложений.

## Изменение и сборка

1. Изменить класс в Source.
2. Выполнить powershell -NoProfile -ExecutionPolicy Bypass -File Scripts/Sync-Sources.ps1.
3. Выполнить Build.cmd.
4. Запустить проверки из Tests: Verify.ps1, Verify-IpaMetadata.ps1, Verify-Updater.ps1, Verify-Design.ps1, Verify-Services.ps1, Verify-Engine.ps1 и Verify-Layout.ps1. Для проверки структуры предварительно создать ZIP через Scripts/Package.ps1. WPF-проверки запускать в Windows PowerShell с -STA.
5. Для выпуска повысить AppInfo.Version и версию в MainWindow.xaml, добавить changelogs/vX.Y.Z.md и синхронизировать исходники.

Файлы Generated/Core.cs, Generated/App.cs, Generated/IpaMetadata.cs, Generated/WindowTheme.cs и Generated/GuiUpdater.cs генерируются из Source. Их можно компилировать прежним Build.cmd без дополнительных пакетов. Для совместимости с обновлением 0.1.6–0.1.12 ZIP содержит служебные копии прежних путей. При первом запуске InstallationLayout раскладывает ресурсы по новым папкам и убирает только копии, совпадающие с содержимым текущей сборки. Изменённые пользователем файлы сохраняются. Следующие обновления работают напрямую с новой структурой.

CI проверяет совпадение генерируемых копий с Source перед сборкой. В готовом ZIP находятся эти копии; для разработки используется репозиторий.

## Проверки

Существующие сценарии проверяют очереди, процессы, отмену, метаданные, обновление/откат, WPF-шаблоны, крестики, журнал и размер окна. Verify-Services.ps1 добавляет проверки с RecordingProcessRunner и проверяет реальные контроллеры окна с отключённым запуском сетевых проверок. Подмена возвращает тестовые ответы и не запускает Apple-утилиты.

AppleSupportService получает данные через IAppleSupportProbe. WindowsAppleSupportProbe только читает список служб и 32-/64-битный реестр; он не запускает службы и не устанавливает драйверы. Проверки различают отсутствие компонентов и невозможность прочитать их состояние. В тестах поставщик подменяется, поэтому установка Apple ПО на сервере сборки не требуется.

## Структура поставки

Assets — иконки; Tests — проверки и фикстуры; Scripts — служебные скрипты; Docs — документация; Generated — переносимые файлы компиляции. В корне остаются EXE, конфигурация, XAML, Build.cmd, Start.cmd, README и лицензия. Source хранится в репозитории для разработки. Встроенные ресурсы обеспечивают переход со старого updater, который извлекает только корневые пути. Package.ps1 формирует ZIP и совместимые копии. Verify-Layout.ps1 проверяет старый updater, миграцию, повторный запуск, сохранение изменённых файлов и компиляцию перенесённой папки.

Сборка инструментов: Tools/DeviceTools и .github/workflows/device-tools.yml. Исходники закреплены SHA; комплект публикуется с --latest=false, чтобы GUI updater продолжал получать только интерфейс. DeviceSource/PreviousDeviceSource различают наш и прежний комплект при миграции и откате. IPA_Downloader используется только AppCatalog.

## Очереди, наборы, хранилище и диагностика

AppSetStore хранит AppSets.json отдельно от state.json. AppSetRules проверяет формат и объединяет ID, AtomicFile атомарно заменяет конфигурацию. Наборы сохраняют только ID и названия; аккаунты, телефоны и версии IPA в них не закреплены. Прежние записи Files читаются только для миграции по метаданным IPA. ResolveMany сначала разрешает все выбранные наборы, затем одной записью сохраняет миграцию: ошибка одного набора не оставляет частично обновлённую конфигурацию.

AppSetsController владеет обоими интерфейсами наборов. Обе кнопки сохранения дополняют набор, а не перезаписывают его. Множественный выбор ListBox позволяет объединить несколько наборов одной операцией. DownloadSelection.AddMissing исключает повторы и сохраняет ранее выбранный VersionID. До вызова AddMissing весь вход проверяется, чтобы некорректный ID не оставил частичную очередь.

StorageController получает тот же снимок LocalRow, что и FilesController, и отвечает только за сводку хранилища и выбор старых версий. Удаление проходит через единый сценарий FilesController с подтверждением и корзиной. AppInfo содержит единственные значения версии и репозитория, используемые C#-кодом.

BatchRunner выполняет последовательные пакеты загрузки и установки: ошибка элемента не останавливает остальные, отмена прерывает пакет и не записывает ожидающие элементы в ошибки. Обработчики UI продолжаются в исходном SynchronizationContext, сами операции выполняются асинхронными сервисами. SearchController и FilesController хранят отдельные снимки ошибок, сохраняя ID версии при повторе загрузки. Отмена не добавляет не начатые элементы в ошибки. Повтор загрузки более старой версии не убирает отдельно выбранную новую версию того же приложения.

QueueProgress получает PROGRESS:N из ipatool и проценты ideviceinstaller, сохраняет состояние под lock и отрисовывается таймером Desktop. ProcessRunner подавляет повтор одинаковых процентов; обновления не заполняют журнал. Объём/скорость отображаются только при наличии в выводе.

IpaMetadata читает корневые iTunesMetadata и Info.plist основной Payload/*.app в XML/binary формате с ограничением размера. LocalAppRepository кэширует метаданные по пути, размеру и времени изменения. StorageAnalysis сравнивает числовые версии в группе bundle ID + Apple Account; неизвестные данные не дают кандидатов на удаление. Удаление использует существующую проверку Downloads и корзину.

DiagnosticReport очищает снимок журнала до записи: структурированные секреты JSON/plist, заголовки, аргументы CLI, почту, профильные пути и идентификаторы устройств. Экспорт не включает state.json, файлы сессии, IPA или сетевую отправку. Verify-WorkflowFeatures.ps1 проверяет наборы, границы путей, метаданные, изоляцию аккаунтов, прогресс и очистку отчёта; Verify-Services.ps1 проверяет связь контроллеров с новыми кнопками.

## Правила сопровождения

- Комментарии к классам в Source описывают ответственность; комментарии к методам объясняют контракты, ограничения и причины нетривиальных решений.
- Контроллеры не запускают процессы и не разбирают IPA напрямую. Сервисы не получают ссылки на WPF-контролы.
- Снимки очередей копируются перед запуском. ID приложения и путь IPA используются как разные ключи; название не является идентификатором.
- Настройки и наборы используют одну AtomicFile.WriteUtf8. Уникальный временный файл очищается даже при ошибке, исходный файл остаётся на месте.
- Изменения в Source требуют обновления Generated через Sync-Sources.ps1. Комментарии входят и в переносимые снимки.
- Verify-Services проверяет несколько наборов одновременно, пересечение ID, сохранение выбранной версии, повторное добавление и перезапуск хранилища. Verify-WorkflowFeatures проверяет продолжение пакета после ошибки, отмену и целостность записи.


## Диалоги и отчёты 0.2.0

AppDialogs создаёт окна с владельцем, общими ресурсами темы и DWM-оформлением. Сведения об IPA используют снимок LocalRow, сведения об устройстве запрашиваются DeviceService.DetailsAsync одним вызовом CLI с таймаутом. Настройки находятся в основной вкладке; диалоги используются для сведений и отчётов.

AppSetEditor редактирует копии строк. AppSetStore.Update валидирует имя, ID и конфликт другого набора, затем одной атомарной записью меняет имя и состав. Отмена диалога ничего не записывает.

OperationReport хранит результаты отдельных приложений и полные сообщения ошибок отдельно от ограниченного журнала. Desktop публикует их в постоянной плашке, а диалог открывается по явному действию. Повтор использует существующие снимки failedDownloads/failedInstalls; доступность кнопки согласована с исходными контроллерами. Закрытие плашки не удаляет последний отчёт.


## Версии и подключение устройств (0.2.3)

`AppVersions` получает ID отдельно от метаданных; `AppVersionWindow` запрашивает только выбранные строки с отменой и ограничением времени. `DownloadSelection.AddVariant` хранит пары App Store ID / VersionID, а `DownloadItem.Key` используется для удаления и завершения конкретного элемента. Старый `Add` сохраняет контракт замены всех версий одного приложения.

`DeviceRow.Network` фиксирует выбранный транспорт; `DeviceService.Arguments` применяет его одинаково к сведениям и установке. USB и Wi-Fi сканируются раздельно. Перед каждой установкой проверяется выбранное устройство и `AppCompatibility` сравнивает данные `IpaMetadata` из подготовленного IPA с текущей iOS. Неизвестные метаданные не означают совместимость. При сетевой ошибке установка не повторяется автоматически.


## Измерения и обвязка Device Tools (0.2.6)

`FileTransferMeter` считает скорость по ограниченному окну монотонных измерений размера. `ApplicationDownloads` раз в секунду проверяет только свой `.tmp`; наблюдатель отменяется и дожидается завершения вместе с запросом. `FILE_TRANSFER` передаётся через существующий канал прогресса, не засоряет журнал и не заменяет процент ipatool. Сброс счётчика и пауза не дают отрицательной либо бесконечной скорости.

`DeviceService` сохраняет прежний API фасада. `DeviceCommandClient` отвечает за транспорт, CLI, таймауты и идентификацию; `DeviceDiscovery` — за независимый поиск USB/Wi-Fi и общий бюджет получения имён; `DeviceInstallation` — за предварительную и повторную проверку IPA. Проверка до staging предотвращает дорогое копирование заведомо несовместимого пакета или пакета для недоступного устройства.

Упаковщик нативного комплекта индексирует папки один раз, вычисляет замыкание DLL через deque и считает SHA-256 потоково. Ревизии исходников в этом выпуске сохранены; изменения процесса сборки не считаются доказательством роста скорости передачи на реальный iPhone.


## Фильтрация локальных IPA (0.2.7)

`LocalFileAccounts` группирует фактические аккаунты из IPA без учёта регистра и крайних пробелов. Статусы отсутствующих/недоступных метаданных объединены в «Без данных об аккаунте», исходный статус остаётся в столбце. `FilesController` хранит полный снимок и фильтрует его в памяти, не сканируя диск при переключении. Очередь `InstallationSelection` независима от фильтра: массовое добавление использует только видимый снимок, обновление сверяет всю очередь со всеми файлами. Счётчик скрытого выбора и подписи версии/аккаунта в подтверждении помогают проверить состав операции.
