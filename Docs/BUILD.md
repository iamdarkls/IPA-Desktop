# Общий цикл сборки и проверки

Поддерживаемые RID, runner и имена архивов перечислены в `Tools/Portable/platforms.json`. Локально и в GitHub Actions используется одна точка входа:

```sh
python Scripts/desktop.py test --rid linux-x64
python Scripts/desktop.py package --rid linux-x64
```

Другие RID: `win-x64`, `osx-arm64`, `osx-x64`. Запускайте команды на соответствующей ОС и архитектуре с .NET SDK 10 и компилятором C для приватного PTY (macOS/Linux). Команда test сама собирает fixture/helper и записывает XML xUnit в artifacts/tests/RID. Она не требует полной компиляции ipatool и libimobiledevice.

Перед package на macOS/Linux нужны нативные инструменты. С пустого рабочего каталога:

```sh
bash Tools/Portable/build-native.sh
python3 Tools/Portable/native-cache.py record --rid linux-x64
python3 Tools/Portable/native-cache.py check --rid linux-x64
python Scripts/desktop.py package --rid linux-x64
```

Системные зависимости перечислены в `.github/workflows/release.yml`. Для macOS задайте PKG_CONFIG_PATH для openssl@3/libzip и CMAKE_PREFIX_PATH для Homebrew, как в workflow. Полная Windows-проверка включает неизменённый helper обновления 0.2.12; Linux/macOS проверяют упакованный GUI без общей установки .NET.

## Кеш нативных инструментов

`native-inputs.json` перечисляет файлы, изменение которых требует пересборки. Ключ дополнительно включает RID и ImageVersion runner. В кеше находятся только готовые инструменты, их контрольные суммы и соответствующие исходники; каталоги компиляции не переносятся между машинами. При изменении исходников, рецепта, ABI образа или архитектуры прежний кеш не принимается.

Для первоначального наполнения кеша `native-seed.json` разрешает только конкретные архивы опубликованной 1.0.0, с закреплёнными SHA-256, совпадающими компиляционными входными файлами и ImageVersion. Новые исходники или другой образ не получают старые бинарники по этому пути. После восстановления проверяются хеши всех файлов, запуск CLI, placeholder, профиль защиты и настоящая C++ логика авторизации с фиктивным транспортом. Затем всегда проверяется упакованное приложение.

Список входов расширяют при добавлении новых исходников/опций нативной сборки. При несовместимом изменении формата кеша увеличивают SCHEMA в native-cache.py. Не используют частичные restore-keys для нативного кеша. Изменение защищённых исходников не должно обходиться заменой версии в манифесте.

## Тесты

Независимые классы xUnit могут работать параллельно (до четырёх коллекций). Desktop UI остаётся эксклюзивной последовательной коллекцией: общий диспетчер Avalonia не используется одновременно разными тестами. Авторизация, отмена процессов и восстановление установки не исключаются из быстрых проверок.

TimeProvider управляет только временем наблюдателя загрузки и фиктивного загрузчика. По умолчанию приложение использует системное монотонное время и прежний интервал в одну секунду. Паузы защиты аккаунта и таймауты реальных процессов не сокращены.

Если версия уже опубликована, обычный push выполняет тесты без сборки новых архивов. workflow_dispatch дополнительно проверяет упаковку этой версии, сохраняя опубликованный релиз. Публикация новой версии возможна только после успеха всех платформ и при совпадении текущего main с проверенным коммитом.
